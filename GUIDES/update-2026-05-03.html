worldsim.bat

Батник запуска для Windows. Создаёт .venv, устанавливает все 7 пакетов, открывает .env при первом запуске. Команды: new, play, worlds, inspect, --install, --update, --help.

02 Что обнаружили — тест-прогон 8 БАГОВ

Запустили test_run.py — headless прогон на 3 хода. Мир генерировался по содержанию правильно, но система падала на pydantic.ValidationError при каждой попытке. Каждый запуск — новая ошибка на новом поле.

B1
extract_json — не было try/except вокруг code-fence парсинга. → если закрывающий ``` отсутствует — исключение не ловится, падение.
B2
max_tokens=8192 в world_init. Ответ LLM ~20 000 символов → JSON обрезается, закрывающий ``` не попадает в ответ. → Увеличено до 16 000.
B3
Character.goals — LLM возвращал ["строка"] вместо [{"text":"…","priority":0.5}]. → Добавлен coerce в _assemble_snapshot.
B4
Faction.public_role — обязательное поле, LLM его пропускал. → Fallback на поле description.
B5
Character.hidden_traits / public_traits / knowledge / goals — LLM возвращал null вместо []. → Нормализация всех list-полей в coerce.
B6
Character.location_id — отсутствовало у персонажа игрока (pc), хотя поле обязательное. → Fallback на первую локацию мира.
B7
Arc.title — LLM использовал name вместо title. Arc.involved_entities — вернул {"characters":[…],"factions":[…]} вместо плоского списка ID. Те же проблемы повторились в PlotState.active_arcs. → Coerce для Arc в обоих местах.
B8
PatchOp.entity_type — LLM использовал "player" вместо enum-значения "player_progression". → Обнаружен на первом ходу, не исправлен (заблокирован на B7).
03 Корневая причина АНАЛИЗ

Один LLM-вызов генерирует 8 типов сущностей и ~40 объектов в одном JSON. Промпт world_init.md не содержит inline-схем полей — только верхнеуровневый пример структуры. LLM угадывает типы вложенных объектов и систематически ошибается на одних и тех же полях.

p_success = 0.97^40 ≈ 0.29 → ~70% запусков падают с ValidationError

Каждый прогон открывал новый баг на другом поле: coerce-слой только маскирует симптомы, не устраняет причину. Система написана архитектурно правильно — проблема только в одном: world_init слишком большой для одного вызова.
